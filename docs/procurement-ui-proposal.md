# 采购实践场景与界面模板提案

日期：2026-10-14。状态：页面模板已确认，VXE 已接入；料品分类已实现正式树表、编辑/详情抽屉及后端接口，采购单据尚未实现。

## 建议结论

保留 Element Plus 作为页面、表单、选择器、抽屉、弹窗和反馈组件。新业务中的列表与单据明细采用 VXE Table 的开源核心，通过集中配置适配。已有若依系统管理页面继续使用当前表格。

基础档案采用“列表 + 详情/编辑抽屉”；采购单据采用“列表 + 独立编辑/详情页”，另提供只读抽屉快速查看。档案字段较多或有多个复杂子表时，允许进入独立页面。

采购业务先跑通下述闭环，再在同一业务上实践 SSO、审批和企业 Agent。本文为设计提案，不代表已实现采购后端业务。

## 业务闭环

```mermaid
flowchart LR
  A[料品 / 供应商 / 仓库 / 货位] --> B[采购订单]
  B --> C[采购到货单]
  C --> D[采购入库单]
  D --> E[库存流水与余额]
```

- 采购订单表达买什么、向谁买、数量、价格与交期。
- 到货单引用订单行，登记实际到货、验收合格和拒收数量。订单可分批到货。
- 入库单引用已确认到货单的合格行，分配仓库、货位并登记入库数量。到货可分批入库。
- 库存只在入库单确认记账时增加；订单提交和到货确认均不增加可用库存。
- 审批状态与履约进度分开表达。例如“已审核 / 部分到货”，避免把两种状态混成一个无法扩展的枚举。
- 来源关系精确到行。记录 `sourceDocumentId`、`sourceLineId`，累计下游数量，不能只存一个可编辑的来源单号。

## 基础数据范围

| 档案     | 首期字段与规则                                                                                 |
| -------- | ---------------------------------------------------------------------------------------------- |
| 料品     | 编码、名称、规格型号、分类、基本单位、采购单位、税率、允许采购、启停状态；分类和单位为受控引用 |
| 供应商   | 编码、名称、联系人、联系方式、地址、默认币种、付款条件、启停状态；银行账号与结算功能后续扩展   |
| 仓库     | 编码、名称、所属组织、负责人、启停状态                                                         |
| 货位     | 所属仓库、货位编码、名称、启停状态；货位编码在所属仓库内唯一                                   |
| 公共字典 | 单位、币种、税率、付款条件；存货分类单独建表；单位换算必须明确，不默认为一比一                 |

数量、单价、金额在后端使用明确精度的 `BigDecimal`；统一逐行舍入和汇总规则。前端金额只用于录入预估，最终结果以后端重算为准。单据行保存料品名称、规格、单位、供应商名称等必要快照，避免后续档案修改改变历史单据。

已锁定并接入 `vxe-table` 4.22.4、`vxe-pc-ui` 4.20.1、`@vxe-ui/plugin-render-element` 4.4.3，公共接入配置位于 `src/plugins/vxe.ts`。`@vxe-ui/plugin-export-xlsx` 4.5.4 仅核验元数据，尚未安装。

料品分类直接使用 VXE 原生列功能：编码、名称、显示顺序和修改时间支持同级节点排序；编码、名称和状态支持列筛选。列筛选与顶部查询共享条件，由后端保留匹配节点的祖先。刷新和保存沿用已生效的筛选与排序，重置同时清除两者；筛选弹层及查询框中的未提交输入不参与刷新请求。

`@vxe-ui/plugin-export-xlsx` 的官方说明覆盖 XLSX 导出，不据此承诺 XLSX 导入。业务文件导入统一走后端解析、权限检查、逐行校验与预览确认，避免各表格页面形成不同规则。

## 模板一：基础档案单表

列表布局依次为：页面标题与主操作、常用查询条件、高级筛选展开区、批量操作与表格工具栏、数据表格、分页。料品编码和名称固定在左侧，操作列固定在右侧，状态采用文字与颜色共同表达。

交互规则：

- 点击编码/名称打开只读详情抽屉；“编辑”进入同一抽屉的编辑模式。
- 抽屉按“基本信息 / 采购设置”组织字段，首期只显示需要的字段；保存后刷新当前列表并保留筛选、分页和选中位置。
- 编码按唯一规则校验；已被单据引用的档案优先停用，删除由后端检查引用关系。
- 关闭未保存抽屉时确认是否放弃修改。查看模式可以直接关闭。
- 导入为“模板选择 → 上传/粘贴 → 校验预览 → 确认导入”；错误定位到行、字段，不能整批静默跳过。
- 新增或编辑成功后可选择继续新增；不强制每次离开列表。

## 模板二：表头 + 表体单据

列表复用基础列表结构，增加单据日期范围、供应商、审批状态、履约状态和来源单号。点击单号进入只读详情页；明确的“编辑”操作进入独立编辑页。

编辑页布局：

1. 页头：返回、单号、审批与履约状态、未保存标识、保存草稿及当前允许的业务操作。
2. 表头：供应商、日期、采购组织、采购员、币种、付款条件与备注，按业务类型调整。
3. 明细工具栏：选择料品、增行、复制行、删行、批量录入；来源单据选择由业务类型决定。
4. 明细表格：稳定行 ID、序号、料品、规格、单位、数量、单价、税率、交期与备注；金额列只读计算。
5. 表尾：明细行数、不含税金额、税额、价税合计。不同单位的数量不盲目加总。
6. 辅助页签：关联单据、业务操作记录；详情页复用相同结构，以只读方式呈现。

采购单据以整页为默认：较宽的明细区更适合连续录入、多窗口对照、地址分享和未完成草稿恢复。抽屉适合快速查看与短编辑；密集明细编辑需要频繁横向滚动，因此作为备选而非默认。

### 不同单据的表体差异

| 单据     | 关键字段                                   | 确认时规则                                                             |
| -------- | ------------------------------------------ | ---------------------------------------------------------------------- |
| 采购订单 | 料品、采购数量、单位、单价、税率、交期     | 供应商与料品有效，数量大于零，金额由后端重算                           |
| 到货单   | 来源订单行、未到货量、本次到货、合格、拒收 | 本次数量不能超过允许的未到货量；合格 + 拒收 = 到货；不改变库存         |
| 入库单   | 来源到货行、可入库量、本次入库、仓库、货位 | 只接收合格且未入库数量；货位属于所选仓库；确认后原子写入库存流水和余额 |

首期不允许超订单到货与超合格数量入库。超收容差、质检流程、退货、批次和序列号后续独立扩展。

### 表格交互验收

- Enter/Tab/Shift+Tab 连续录入，中文输入法组合输入期间不抢占确认键。
- 数量、金额、日期校验显示在具体单元格；提交时滚动并聚焦首个错误。
- 草稿行可拖拽排序，也提供键盘或上移/下移操作；使用稳定行 ID，不能依赖数组下标识别来源行。
- 有排序、筛选或跨页视图时禁用业务行拖拽，防止显示顺序与真实顺序混淆。
- 列宽、列顺序、显隐和筛选方案按“用户 + 页面”保存；业务行顺序随单据保存。
- 导入和粘贴先解析与预校验；未知料品、停用供应商、无效单位或超量来源行必须明确报错。
- 已提交/审核单据的可编辑性由后端状态机决定，前端只呈现允许的操作。
- 验收 10、100、500 行与不同屏幕宽度，验证冻结列、合计、焦点和虚拟滚动，不能仅以演示数据流畅判断性能。

## 复用边界

当前分类页先完整使用 VXE 原生功能，继续通过 `useVxe` 统一语言和主题，暂不封装通用表格组件。待料品档案和采购订单形成真实页面后，再按重复需求提炼 `BusinessListPage`、`MasterDataDrawer`、`DocumentEditorPage`、`DocumentLinesGrid`。各业务页持有自己的强类型查询参数、表头与行模型，保留 VXE 原生配置、插槽和事件的使用能力。

共享的是布局和交互协议：筛选、分页、列偏好、加载与空状态、脏数据提示、明细增删、错误定位。业务字段、金额规则、来源关联、审批与记账规则由业务模块负责。先以料品和采购订单验证抽象，再推广到供应商、仓库、到货与入库，避免首期构建通用低代码引擎。

## 后端与权限契约

- 列表采用服务端分页、筛选、排序；排序字段建立白名单。导出明确区分“已选行”和“当前查询全部结果”，不能把当前页冒充全部数据。
- 导入、导出、查询、提交、审核、确认入库分别定义权限，例如 `purchase:order:list`、`purchase:order:submit`、`inventory:receipt:post`。
- 详情、编辑、删除、来源选择、导入和导出都执行数据范围检查；按钮隐藏只用于界面反馈。
- 单据草稿保存采用乐观锁版本号；来源剩余数量和入库记账在事务中校验，重复确认使用幂等键，防止多标签页或重试造成超收、重复入库。
- 已记账单据通过有权限的冲销流程更正，不能直接修改历史库存流水。

## 实践 SSO 与企业 Agent

SSO：员工由企业身份提供方登录，映射本地用户、组织、角色；本地业务权限与数据范围继续生效。供应商门户可作为第二个应用，验证同一身份体系下的应用权限边界。

Agent：先提供料品/供应商/订单/库存的只读检索，再增加“根据需求生成采购草稿”“解释到货差异”“提示未入库到货”等场景。Agent 通过与普通界面共用的业务服务和权限校验执行命令；提交、审核与入库记账要求明确的人为确认，并记录操作者、Agent 调用、来源证据及执行结果。Agent 不直接修改数据库，也不以管理员身份绕过用户数据范围。

## 实施顺序

1. 已确认基础档案抽屉、单据独立页面；已接入 VXE 并完成项目内组件验证。
2. 已建立存货分类表和独立业务模块，按后端、前端顺序实现料品分类；下一步完成单位、存货档案及供应商、仓库、货位。
3. 完成采购订单，验证表头明细保存、权限、乐观锁、导入和导出。
4. 完成到货、入库与库存流水，验证部分履约、来源行关联、幂等与数量约束。
5. 在同一业务流程上接入 SSO、审批和 Agent，不另外搭建无法复用业务规则的演示系统。
